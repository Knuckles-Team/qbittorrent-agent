# CONN-QBITTORRENT-AGENT-SURFACE — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A row names the file it touches and the test that proves it.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-QBITTORRENT-AGENT-SURFACE-R001` | **Every WebUI API operation is one tool.** The connector must serve one typed tool for each qBittorrent WebUI API operation. The census fixture `tests/fixtures/upstream_operations.json` lists 121 operations read from the qBittorrent release-5.2.4 controllers (`src/webui/api/*controller.h`) with the POST-only actions of `src/webui/webapplication.h`; it excludes only `auth/login` and `auth/logout` (web sign-in). `scripts/generate_api_client.py` writes `qbittorrent_agent/api/client.py`: one class per scope and one method `<scope>_<action>` per operation, with typed keyword parameters and a `VERB /api/v2/<route>` docstring line. Before this row the connector served 88 hand-written tools, 33 operations had none, and `pause`/`resume` called routes qBittorrent 5.x removed. Caller chain: `qbittorrent_agent:connector` (`qbittorrent_agent/__init__.py`, `Connector(api=QbittorrentApi)`) -> `scion_sdk` method-tool registration -> one tool `qbittorrent_<method>` per public method. Shape: `class Api(AppApi, ClientDataApi, LogApi, RssApi, SearchApi, SyncApi, TorrentCreatorApi, TorrentsApi, TransferApi)`. | Each fixture operation has a client method, each client route is an upstream operation, each method is a served tool. Test: `tests/test_surface.py::test_every_upstream_operation_has_a_client_method`, `tests/test_surface.py::test_every_client_method_is_served_as_a_tool`. |
| `CONN-QBITTORRENT-AGENT-SURFACE-R002` | **Typed tools only.** The connector must serve no `action`-routed tool and no `params_json` parameter. The action-routed `qbittorrent_<domain>` tools of `qbittorrent_agent/mcp_server.py` and `qbittorrent_agent/mcp/mcp_*.py` are removed; `qbittorrent_ingest_torrents` takes typed `filter`, `category`, `tag` and `limit` (`qbittorrent_agent/mcp/mcp_kg.py`). Deleting and removing operations carry `destructiveHint` and ask for confirmation. Caller chain: `qbittorrent_agent:connector` -> `tools="qbittorrent_agent.mcp"` -> `register_kg_tools`. Shape: `register_kg_tools(mcp)` is the only registrar. | No tool has `params_json` or `action`; delete and remove tools are destructive; reads are read-only. Test: `tests/test_surface.py::test_no_action_routed_or_untyped_tool`, `tests/test_surface.py::test_destructive_operations_ask_for_confirmation`. |
| `CONN-QBITTORRENT-AGENT-SURFACE-R003` | **A failed call says why; answers are objects; API-key auth.** `BaseApiClient._handle_errors` (`qbittorrent_agent/api/api_client_base.py`) must raise on every status of 400 or more: `QbittorrentApiError` with the status and qBittorrent's plain-text reason, `UnauthorizedError` on 401 and 403. Before this row a 404 or 409 was only logged and the tool reported success. `BaseApiClient._call` sends GET parameters as the query and POST parameters as the form (booleans as `true`/`false`, objects and lists as JSON), uploads base64 `.torrent` files, and shapes every answer as a JSON object: lists and text under `result`, a `.torrent` file as `content_base64`, an empty answer as `status: success`. A `QBITTORRENT_API_KEY` of the 5.2 form (`qbt_` plus 28 characters) is sent as a bearer token with no login; any other value falls back to the username and password session, so a placeholder never locks the client out. Caller chain: a served tool -> `Api.<scope>_<action>` -> `BaseApiClient._call` -> `_send` -> `_handle_errors`. Shape: `def _call(self, verb, route, params=None, files=None) -> Any`; `def is_api_key(value) -> bool`. | A 409 raises with its reason; a list answer is wrapped; a boolean and a JSON object reach the wire; an export is base64; a valid key is a bearer and a placeholder logs in. Test: `tests/test_surface.py::test_a_failed_call_raises_with_qbittorrents_reason`, `tests/test_surface.py::test_answers_are_json_objects_and_values_travel_on_the_wire`, `tests/test_surface.py::test_api_key_is_a_bearer_and_a_placeholder_falls_back_to_login`. |
| `CONN-QBITTORRENT-AGENT-SURFACE-R004` | **Skills carry the workflows as tool-use contracts.** The package must ship the skills `qbittorrent-torrent-lifecycle`, `qbittorrent-transfer-tuning`, `qbittorrent-download-client`, `qbittorrent-kg-ingestion` and `qbittorrent-agent-operations`. Each workflow is a `qbt:ToolUseContract` in `qbittorrent_agent/ontology/qbittorrent-contracts.ttl` with ordered `qbt:ContractStep` nodes, one `qbt:callsTool` each, `qbt:needsApproval` on writes, and `qbt:ParameterBinding` nodes. 9 contracts: transfer health, stalled-torrent recovery, the `zz-validation` category round trip, add a torrent, share limits, speed limits, diagnosing an app that cannot reach qBittorrent (login failures and IP bans), provisioning an app category, and ingest. Caller chain: the SDK content tier serves `skill://` and `ontology://qbittorrent-mcp/<file>.ttl`. Shape: as `CONN-ARR-MCP-SUITE-R004` with the `qbt:` namespace. | Every contract and skill tool is served; steps are numbered 1..n; every contract's skill exists. Test: `tests/test_surface.py::test_contract_and_skill_tools_are_served`, `tests/test_surface.py::test_contract_steps_are_ordered_and_bound`. |
| `CONN-QBITTORRENT-AGENT-SURFACE-R005` | **Prompts are agent definitions.** The package must ship the operator prompt `torrent_operator` and the role prompts `torrent_download_monitor`, `seeding_manager` and `download_client_steward` in `qbittorrent_agent/prompts/<name>.json`, replacing `torrent_specialist`, which named the removed action tools. Each has `role: system`, `systemPromptFor` a role class, and a `core_directive` with the goal, skills, workflows, data locations, guardrails and outputs; each is a `qbt:ConnectorPrompt` linked by `qbt:usesSkill`, `qbt:runsContract`, `qbt:usesTool` and `qbt:systemPromptForRole`. Caller chain: the SDK prompt provider serves each JSON file as one MCP prompt. Shape: JSON keys `role`, `systemPromptFor`, `identity`, `instructions.core_directive`, `data_locations`, `guardrails`, `outputs`, `skills`, `contracts`, `tools`. | Each prompt is served, names only served tools, has every section, and its ontology links equal its tool list. Test: `tests/test_surface.py::test_operator_and_role_prompts_exist`, `tests/test_surface.py::test_prompt_is_a_complete_agent_definition`. |
| `CONN-QBITTORRENT-AGENT-SURFACE-R006` | **Data location, routing and federation.** `qbittorrent_agent/ontology/qbittorrent.ttl` must record the instance with its setting names (never values), its save paths (`/downloads/complete`, `/downloads/incomplete`), one category per consuming app with its folder, a `qbt:RoutingRule` from each category to its arr app, and a `qbt:FederationLink` for each arr app that sends downloads to qBittorrent. Caller chain: the SDK content tier serves the file; arbora onboarding reads it. Shape: `qbt:instance-qbittorrent`, `qbt:savepath-<name>`, `qbt:category-<app>`, `qbt:route-<app>`, `qbt:federation-<app>-sendsDownloadsTo-qbittorrent`. | The instance has its URL setting and save paths; at least 4 routes and 4 federation links. Test: `tests/test_surface.py::test_data_locations_routing_and_federation`. |
| `CONN-QBITTORRENT-AGENT-SURFACE-R007` | **Every class rolls up to medulla core.** Every class in `qbittorrent_agent/ontology/*.ttl` must be in `http://knuckles.team/kg/qbittorrent#`, subclass a medulla core class and reach `bfo:Entity`, with no `owl:imports`. The earlier file redeclared the core classes `:Torrent`, `:Tracker` and `:TorrentCategory` without a parent; those declarations are gone. Caller chain: the SDK content tier serves both files; the engine merges them with core. Shape: `qbt:<Name> rdfs:subClassOf :<CoreClass>`; parents in [data-model.md](data-model.md). | No import; every class is in `qbt:`, has a core ancestor and reaches `BFO_0000001`. Test: `tests/test_surface.py::test_every_class_reaches_medulla_core_without_imports`. |
| `CONN-QBITTORRENT-AGENT-SURFACE-R008` | **Ingest uses core classes and a served tool.** `qbittorrent_agent/kg_ingest.py` must emit the core classes `Torrent`, `Tracker` and `Category` (was the undeclared `TorrentCategory`). The preset in `qbittorrent_agent/ontology/mappings/source.yaml` and `qbittorrent_agent/connector_sources.py` must name `qbittorrent_torrents_info` with its current schema pin and `records_path: result`, not the removed `qbittorrent_torrents` action tool. Caller chain: `qbittorrent_ingest_torrents` -> `Api.torrents_info` -> `ingest_torrents`. Shape: preset `tool` plus `tool_schema_sha256`, no `action` key. | Every emitted node type is a core class; the preset tool is served with a matching pin. Test: `tests/test_surface.py::test_ingest_uses_core_classes_and_a_pinned_served_tool`. |
