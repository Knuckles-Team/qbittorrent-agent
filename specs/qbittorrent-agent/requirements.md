# CONN-QBITTORRENT-AGENT — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A row names the file it touches and the test that proves it.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-QBITTORRENT-AGENT-R001` | **Session recovery.** The client must log in again and retry once after a 401 or 403 response, in `qbittorrent_agent/api/api_client_base.py`. A second rejection must raise `UnauthorizedError`. Caller chain: an MCP tool calls an operation method of `qbittorrent_agent/api/client.py`, which calls `_call` and then `_get` (`qbittorrent_agent/api/api_client_base.py:116`) or `_post` (`qbittorrent_agent/api/api_client_base.py:123`), which call `_send` (`qbittorrent_agent/api/api_client_base.py:98`); `_send` calls `login` (`qbittorrent_agent/api/api_client_base.py:107`) after a 401 or 403. Shape: `BaseApiClient._send` in `qbittorrent_agent/api/api_client_base.py`; the second rejection raises `UnauthorizedError`. Proving test: `tests/test_session_relogin.py::test_expired_session_logs_in_again_and_retries_once`. | `tests/test_session_relogin.py::test_expired_session_logs_in_again_and_retries_once` and `::test_second_consecutive_rejection_raises_without_looping` must pass. |
| `CONN-QBITTORRENT-AGENT-R002` | **Wiring.** The `_get` and `_post` methods must call `_send` at `qbittorrent_agent/api/api_client_base.py:117` and `:126`. `_send` must call `login` at `:107`. Caller chain: `_get` and `_post` in `qbittorrent_agent/api/api_client_base.py` call `_send`; `_send` calls `login`. Shape: the call sites `_get` (`qbittorrent_agent/api/api_client_base.py:117`) and `_post` (`qbittorrent_agent/api/api_client_base.py:126`) and the `login` call in `_send` (`qbittorrent_agent/api/api_client_base.py:107`). Proving test: `tests/test_session_relogin.py::test_post_also_retries_on_401`. | `tests/test_session_relogin.py::test_post_also_retries_on_401` must observe the retry through `_post`. |
| `CONN-QBITTORRENT-AGENT-R003` | **Hot-path proof.** A public operation must recover from an expired session through the real entry point. Caller chain: a public operation such as `app_version` on the API client calls `_call`, which calls `_send` and the re-login path. Shape: the real `BaseApiClient` of `qbittorrent_agent/api/api_client_base.py` with a faked transport; no stub of `_send`. Proving test: `tests/test_session_relogin.py::test_public_operation_recovers_from_expired_session`. | `tests/test_session_relogin.py::test_public_operation_recovers_from_expired_session` must call `app_version` against a faked transport. |
| `CONN-QBITTORRENT-AGENT-R004` | **Fleet name.** `pyproject.toml` declares `qbittorrent-mcp` as the single `scion_sdk.connector` entry point. The content pack, the manifest `connector`, the fingerprints and the ingest binding all carry `qbittorrent-mcp`. Caller chain: `qbittorrent-mcp` in `pyproject.toml` runs `scion_sdk.cli:serve`, which builds the server from the `scion_sdk.connector` entry point `qbittorrent_agent:connector` (`qbittorrent_agent/__init__.py:93`); `connector_name("qbittorrent_agent")` in the SDK resolves the same entry point name for the content pack, the manifest and the ingest binding. Shape: `pyproject.toml` entry point `qbittorrent-mcp`, the `connector_name` helper of the SDK and the `ConnectorContent`/`IngestBinding` calls under `qbittorrent_agent/`; reuses the SDK name resolution and adds no second constant. Proving test: `tests/test_fleet_name.py::test_connector_name_is_the_fleet_name`. | Every connector name in the package is `qbittorrent-mcp`. |
